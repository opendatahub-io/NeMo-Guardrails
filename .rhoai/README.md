# API contract checks

Pull requests targeting `develop` are checked for OpenAPI compatibility by the
shared checks in
[`red-hat-data-services/contract-tests`](https://github.com/red-hat-data-services/contract-tests).
The checks need no running service or cluster. Both jobs run in **enforce
mode**: breaking OpenAPI findings and coverage gaps fail the pull request. They
are pull-request checks, not promotion gates.

## What is covered

The `api-contract` job runs the static OpenAPI compatibility check for each
contract in `.rhoai/contracts.yaml`, comparing the pull request with a baseline
commit of this repository:

- `fern/openapi.yml` — the Guardrails API Server contract
  (`guardrails-api-v1`)
- `fern/hooks-openapi.yml` — the Guardrails Hooks API contract
  (`guardrails-hooks-api-v1`)

Only paths matching each contract's `matchPath` are compared. For both
contracts, that scope is `^/(v1|healthz)(/|$)`. The root UI route in
`fern/openapi.yml` is intentionally outside the scope.

The `api-contract-coverage` job fails when an OpenAPI document in the
repository is neither a registered contract nor listed with a reason in
`spec.exclusions`. The two tracked OpenAPI conformance fixtures are excluded
because they are test data, not APIs served by this repository.

The experimental OpenAI-compatible proxy remains generated output for
documentation and is intentionally outside the enforced contract set while that
server is work in progress.

Both committed OpenAPI documents are generated by the scripts in `scripts/`.
Run `make docs-fern-generate-openapi` before a contract change, and keep the
generated documents and source changes in the same pull request. Do not edit
the generated documents directly.

## Baseline

The baseline is the commit named in `.github/workflows/api-contract.yml`
(`baseline-refs`), currently `v0.25.0.rc1+rhaiv.1` at
`5dadfe885adc9e698e9731c2919c947b05baac5f`. It must be a full commit SHA;
branch names, tags and `HEAD` are rejected.

The two OpenAPI artifacts are absent from that baseline, so the contract run
that introduces them reports `status: new`. After this change merges, later
pull requests compare against their merge-base and fail when a relied-on API
path, parameter, request field, response field or status shape is removed or
narrowed. Moving the baseline forward is an intentional compatibility decision
and needs reviewer approval from someone other than the author.

## Update the baseline

Resolve the new release tag to a full commit SHA and confirm both contract
artifacts exist there:

```sh
git fetch origin --tags
baseline=$(git rev-parse <release-tag>^{})
git cat-file -e "$baseline:fern/openapi.yml"
git cat-file -e "$baseline:fern/hooks-openapi.yml"
```

Replace the recorded baseline in `.rhoai/contracts.yaml`,
`.github/workflows/api-contract.yml`, and this file. Then rerun both `check`
commands and `coverage` with the new SHA. If a check reports a break, fix it or
record a per-contract baseline override with its reason and approval link.
Baseline changes require review from someone other than the author.

## Run it locally

Use the same `contract-tests` ref as the workflow and the exact tool versions
pinned in `.rhoai/contracts.yaml`, so local results match CI.

```sh
git clone https://github.com/red-hat-data-services/contract-tests.git ../contract-tests
git -C ../contract-tests checkout --detach d63fe27957117fd99161a693c7fdef9e20efb9d9

GOBIN="$PWD/bin" go install github.com/oasdiff/oasdiff@v1.33.0
GOBIN="$PWD/bin" go install github.com/mikefarah/yq/v4@4.45.1

baseline=5dadfe885adc9e698e9731c2919c947b05baac5f
rm -rf /tmp/guardrails-api-contract-report
python3 ../contract-tests/cmd/contract-tests/cli.py check \
  --repo . \
  --contract-set .rhoai/contracts.yaml \
  --contract-id guardrails-api-v1 \
  --baseline-ref "$baseline" \
  --oasdiff bin/oasdiff \
  --yq bin/yq \
  --output-dir /tmp/guardrails-api-contract-report

rm -rf /tmp/guardrails-hooks-api-contract-report
python3 ../contract-tests/cmd/contract-tests/cli.py check \
  --repo . \
  --contract-set .rhoai/contracts.yaml \
  --contract-id guardrails-hooks-api-v1 \
  --baseline-ref "$baseline" \
  --oasdiff bin/oasdiff \
  --yq bin/yq \
  --output-dir /tmp/guardrails-hooks-api-contract-report

python3 ../contract-tests/cmd/contract-tests/cli.py coverage \
  --repo . \
  --contract-set .rhoai/contracts.yaml \
  --baseline-ref "$baseline" \
  --yq bin/yq \
  --yq-version 4.45.1
```

For `check`, read `report.json.status` in the output directory as well as the
exit code. The first run for a newly committed artifact reports `new`; after
the artifact exists at the baseline, a breaking finding makes the command exit
nonzero. `coverage` ends with `Result: complete` when every OpenAPI document is
registered or excluded. Add `--json-output <file>` for a machine-readable
coverage report.
